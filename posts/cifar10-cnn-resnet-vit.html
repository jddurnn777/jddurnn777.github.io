EEL4810, Team Project

CNN vs. ResNet-18 vs. Vision Transformer on CIFAR-10

Fine-tuning beats feature-freezing, and a corrupted download taught me when to cut my losses.

Tldr; For our EEL4810 final project, my team compared four ways to classify images: a small CNN built from scratch, a pretrained ResNet-18 with its backbone frozen, the same ResNet-18 with its last block fine-tuned, and a Vision Transformer built from scratch. Fine-tuning the ResNet-18 won by a lot at 94.47% test accuracy, about 15–17 points better than both the from-scratch CNN and the frozen ResNet. Just having pretrained features wasn't enough. Letting even part of the network adapt was what mattered. The Vision Transformer hit 99.20%, but on MNIST instead of CIFAR-10 because of a broken dataset download, so it's not a fair comparison.

Who did what

This was a four-person final report for EEL4810. Marcus Francois, Yahir Garcia, Ido and I split the methodology across four notebooks. My pieces were:

  • The from-scratch baseline CNN (solo).
  • The evaluation metrics for the frozen ResNet-18 (with Yahir, who designed and built the initial ResNet-18 model).
  • Fine-tuning and evaluating the ResNet-18 (with Ido and Marcus). Ido wrote the initial training and evaluation loop, Marcus tuned the learning rate, and I adjusted the number of epochs and built out the evaluation side: the confusion matrix, classification report and per-class analysis.
  • The Vision Transformer built from scratch (with Marcus).

I'm writing up the whole comparison for context, but I'll be clear throughout about which parts were mine.

The question

Image classification on CIFAR-10 is a classic way to ask a really practical question: is it better to train a small model from scratch, or borrow features that a much bigger model already learned on a huge dataset like ImageNet? Training from scratch is cheap and you control everything, but the model only knows what it can learn from your data. Borrowing a pretrained model gives you a head start, but that model learned on different images for a different task.

So we tested four points along that spectrum: a CNN with zero pretraining, a frozen pretrained backbone, a partly fine-tuned pretrained backbone, and a Vision Transformer built entirely from scratch.

The dataset: CIFAR-10

CIFAR-10 is 60,000 small color images, 32×32 pixels each, split evenly across 10 classes: airplane, automobile, bird, cat, deer, dog, frog, horse, ship and truck. 50,000 are for training and 10,000 for testing. Since every class has the same number of images, plain accuracy is a fair metric here. There's no class that a model could get a high score on by just guessing it all the time.

What makes it harder than it sounds is how small the images are. At 32×32, a cat and a dog, or a truck and a car, can look really similar, even to a person. That comes up a lot in the results.

For every model, we split the original 50,000 training images 80/20 into a training set and a validation set. The validation set is used during training to catch overfitting, and the 10,000 test images are only used once at the end for the final score.

Background: the three kinds of models

Convolutional neural networks (CNNs)

A CNN slides small filters (usually 3×3) across the image. Each filter learns to respond to a specific pattern, like an edge or a patch of color. Stacking layers lets the network build up from simple patterns to more complex ones: edges, then textures, then shapes, then parts of objects. Pooling layers shrink the image between convolution layers, which cuts down the computation and lets deeper layers "see" a bigger area of the original image. At the end, a small fully connected classifier turns those features into a score for each class.

ResNet-18 and transfer learning

ResNet (residual network) was a big step for deep CNNs. Very deep networks used to get worse as you added layers, because they became hard to train. ResNet fixes that with skip connections: each block adds its input back onto its output, so it only has to learn the difference from what came in. ResNet-18 is the 18-layer version, and the one we used was pretrained on ImageNet, which has over a million images in 1,000 classes.

Transfer learning means taking that pretrained model and adapting it to your own dataset. There are two main ways to do that, and comparing them was the point of our project:

  • Frozen feature extractor: lock all the pretrained layers and only train a new final layer. The network turns every image into the same features it would have for ImageNet, and you only learn how to map those features to your classes.
  • Fine-tuning: let some (or all) of the pretrained layers keep learning, usually with a small learning rate, so the features can adjust to your data.

Vision Transformers (ViTs)

A Vision Transformer takes the transformer architecture from language models and applies it to images. Instead of sliding filters around, it chops the image into small square patches and treats each patch like a word in a sentence. Then self-attention lets every patch look at every other patch and decide which ones matter for understanding the image. The tradeoff is that CNNs have built-in assumptions about images (nearby pixels are related), and ViTs don't, so ViTs usually need a lot more data or a lot of regularization to train well from scratch.

Baseline: a CNN from nothing (my part)

The architecture

My starting point was a plain CNN in PyTorch, meant to set a baseline for what you can do with no pretraining at all:

  • Three convolution blocks, each Conv2d → ReLU → MaxPool2d, with the number of channels going 3 → 32 → 64 → 128. All the filters are 3×3, and each pooling layer shrinks the image, so deeper layers work on smaller, more abstract feature maps.
  • A small classifier: flatten → Linear (256) → ReLU → Dropout(0.3) → Linear (10), one output per class.

One thing that took some debugging was the tensor sizes. Since pooling shrinks the image, the flattened feature vector has to exactly match the input size of the first linear layer (128 channels times whatever height and width are left). If you get that wrong, PyTorch throws a shape mismatch error, and I had to carefully track the size through every layer to fix it.

Training setup

  • Batch size 128, a common choice that balances speed with stable gradients.
  • Adam optimizer with a learning rate of 0.001 (Adam's default) and weight decay of 0.0001, which adds L2 regularization to discourage large weights.
  • Cross-entropy loss, the standard for multi-class classification.
  • 15 epochs, enough for a small CNN to converge on CIFAR-10.
  • Normalization with a mean and standard deviation of 0.5 per channel, from the official PyTorch CIFAR-10 tutorial, which centers the pixel values around zero.
  • A fixed random seed across Python, NumPy and PyTorch (including CUDA), so the data split and training are reproducible.

Fixing the overfitting

The first run overfit. Training accuracy kept climbing while validation accuracy plateaued, which is a pretty textbook sign the model was memorizing the training images instead of learning general patterns. So I added two kinds of data augmentation:

  • Random horizontal flips: a mirrored car is still a car.
  • Random cropping with padding: pad the image a little, then crop it back to 32×32 at a random spot, so the object isn't always in exactly the same place.

Essentially augmentation makes the training set look slightly different every epoch, so the model can't just memorize it. I also tried dropout rates from 0.3 to 0.5 and weight decay from 1e-4 to 1e-3 to find a balance between overfitting and underfitting, then retrained the best configuration from scratch. Augmentation took test accuracy from 77.45% to 79.96% and made the validation curve a lot more stable.

Transfer learning, two ways

Frozen ResNet-18 (Yahir and me)

Yahir built the frozen ResNet-18 model, and I worked on the evaluation metrics with him. The setup:

  • Resize the images from 32×32 to 224×224, the input size ResNet-18 was trained on.
  • Normalize with ImageNet's mean and standard deviation instead of 0.5, since pretrained weights work best when the new images are processed the same way as the images they were trained on.
  • Swap the final layer. The original ResNet-18 outputs 1,000 ImageNet classes, so it was replaced with a new linear layer with 10 outputs.
  • Freeze everything else by setting requires_grad = False on all the pretrained layers, so only the new final layer learns.

We kept the seed, batch size, validation split and evaluation process the same as my CNN, so any difference in results would come from the model, not the setup.

Fine-tuned ResNet-18 (Ido, Marcus and me)

For the fine-tuned version, we froze the whole network and then unfroze just the last residual block (layer4) and the classifier. The earlier layers stayed frozen because they learn general things like edges, colors and textures that transfer well to any image. The last block learns more specific, higher-level features, so that's the part worth letting adapt to CIFAR-10.

The other changes:

  • A much lower learning rate (1e-4). Pretrained weights need gentler updates than randomly initialized ones. A big learning rate can wreck the useful features the model already has instead of adjusting them.
  • AdamW with weight decay 1e-4, only applied to the unfrozen layers. AdamW handles weight decay separately from the gradient update, which works better for regularization than regular Adam.
  • 14 epochs, which is the part I adjusted. It gave the model enough time to improve without training long after validation performance leveled off.
  • A fuller augmentation pipeline: horizontal flips, random crops with padding, color jitter (brightness, contrast and saturation), and small random rotations up to 15°.
  • Label smoothing (0.1), which keeps the model from putting 100% of its confidence on one class during training and helps with overconfidence.

On the evaluation side, I set it up so the evaluation function returned the labels and predictions, not just the accuracy, so we could build a confusion matrix, classification report and per-class accuracy. I also fixed a bug where predictions weren't being moved from the GPU back to the CPU before being converted to NumPy arrays, which caused errors when calculating the metrics.

Vision Transformer from scratch, and a dead end that became MNIST

What happened with CIFAR-10

Marcus and I built the ViT, and I used Akshay Gokhale's guide on training a ViT on CIFAR-10 as the main reference. The plan was to run it on CIFAR-10 like everything else. It didn't cooperate. The dataset download failed with a 503 error, and when I tried to extract the archive manually, the file was corrupted. Under a real deadline, we swapped in MNIST (handwritten digits) so we could still fully build, train and validate the transformer instead of spending the rest of the project debugging a download.

MNIST is grayscale and much easier than CIFAR-10, so the ViT results aren't an apples-to-apples comparison. That's exactly the caveat I'd want if I were reading someone else's report.

How the model works, step by step

  1. Resize to 32×32. MNIST images are 28×28, but I kept the 32×32 size from the guide. Since MNIST is grayscale, I changed the input channels from 3 to 1.
  2. Patch embedding. The image is split into 4×4 patches, which gives (32 / 4) × (32 / 4) = 64 patches. Instead of slicing the image by hand, a convolution with a 4×4 kernel and a stride of 4 steps across it in non-overlapping blocks and turns each patch into a 192-number vector (the embedding). Essentially each patch becomes one "token."
  3. CLS token. A learnable extra token gets added to the start of the sequence, so there are 65 tokens total. It acts like a summary of the whole image, and at the end the model uses it to make the classification.
  4. Positional embeddings. Transformers don't naturally know where each token came from. Without these, the model would know what patches exist but not where they were in the image, so a learnable position vector gets added to each token.
  5. Multi-head self-attention. Each token makes a query, key and value. Comparing every query to every key gives attention scores, which get scaled so they don't get too large, turned into probabilities with softmax, and used to mix the values. I used 3 heads, each looking at part of the 192-number embedding.
  6. MLP and pre-norm blocks. After attention, a small MLP with GELU activation processes each token. Each transformer block has a residual path around the attention and another around the MLP, and applies LayerNorm before each one (pre-norm), which helps keep training stable.
  7. Stack 12 blocks, then normalize, take the CLS token's output, and pass it through a final linear layer with 10 outputs.

That came out to about 5 million parameters, similar to the ViT-Tiny size the guide recommended. A smaller transformer makes more sense for a small dataset, since a big one would overfit.

Training it

  • MixUp and CutMix. MixUp blends two images together and blends their labels by the same amount. CutMix pastes a rectangle from one image onto another and mixes the labels based on how much of each image is showing. Since the labels become "soft" (like 70% a 3, 30% a 7), I used a soft-target cross-entropy loss instead of the normal one.
  • AdamW for the optimizer.
  • OneCycleLR as the learning rate scheduler. The learning rate starts low, ramps up to a max, then comes back down, which is usually more stable than a fixed rate for transformers.
  • Gradient clipping to prevent unstable updates, which can happen when training transformers.
  • 30 epochs, saving the model every time validation accuracy improved, so the final test used the best version, not just the last epoch.

Validation didn't use MixUp or CutMix, since the point of validation is to test on clean images.

Bugs along the way

Building this from scratch meant a lot of small mistakes. One was accidentally writing == instead of = when defining the attention block's output projection, so Python treated it as a comparison instead of creating the layer. That layer is what combines the attention heads back together, so it mattered. Others were typos like supter instead of super, and putting the forward() method in the wrong place. My main takeaway: model code is really sensitive to tiny syntax and indentation mistakes, and some of them don't crash, they just quietly make the model wrong.

Accuracy was the main metric, since CIFAR-10 is balanced. For the fine-tuned ResNet-18 and the ViT, we also reported the F1 score, which balances precision (when the model says "cat," how often is it right) and recall (of all the real cats, how many did it find).

The from-scratch CNN

77.45% without augmentation, 79.96% with it. Augmentation clearly helped with overfitting, but the overall performance was still limited. That's expected: the CNN is shallow, it has to learn every feature from scratch, and CIFAR-10 has a lot of classes that look alike.

Pretrained features alone weren't enough

The frozen ResNet-18 landed at the same accuracy as the un-augmented CNN baseline, 77.45%. That tells me simply having access to ImageNet's pretrained features bought us nothing by itself. The backbone's features were frozen and couldn't adapt to CIFAR-10's specific patterns, so the model was stuck with whatever a single trainable layer could get out of features tuned for a totally different dataset. It converged quickly, but it also hit its ceiling quickly.

Fine-tuning is what actually mattered

This is the one that actually surprised me. Unfreezing just the last residual block and fine-tuning with a low learning rate jumped accuracy to 94.47%, a 15–17 point improvement over both the frozen model and the from-scratch CNN. Letting even a small part of the pretrained network adapt to the target dataset mattered way more than which model we started from. The training curves also showed steady improvement in validation accuracy with very little overfitting.

Where the best model still got confused

The confusion matrix for the fine-tuned model showed strong performance on frog, truck, automobile and airplane, and weaker performance on cat and dog. The most common mistakes were the ones you'd expect from a person squinting at tiny images too:

  • Dog predicted as cat was the most common mistake, and cat predicted as dog was second.
  • Truck predicted as automobile 29 times, and automobile as truck 24 times.
  • Airplane predicted as ship 18 times, and ship as airplane 14 times.

So visually similar classes stay hard even for a 94%-accurate model.

The Vision Transformer

99.20% accuracy and an F1 of 0.99 on MNIST, with near-perfect classification across every digit. That shows the architecture was built correctly and can learn, but it doesn't prove it would beat a CNN on CIFAR-10. MNIST is grayscale, has much less variation, and the classes are easier to tell apart. The high score says more about the dataset than the architecture.

What I took away from this

  • Augmentation helps generalization. It improved every model we used it on.
  • Pretrained features need to adapt. A frozen backbone did no better than a small model from scratch. Fine-tuning even one block made the biggest difference in the whole project.
  • Model capacity matters. The small CNN struggled because it didn't have enough depth to represent CIFAR-10's complex features. ResNet-18 did.
  • The dataset shapes the result. The ViT's 99% says more about MNIST being easy than about transformers being better.

What I'd do differently

  • Confirm a dataset downloads and extracts cleanly before building the model that depends on it. The CIFAR-10 → MNIST swap cost us a clean comparison.
  • Reload the model from pretrained weights before any additional retraining run, so each run is independent. For our fine-tuning retraining, the model should have been reset first instead of continuing from the previous run's state.
  • Update deprecated code. We loaded ResNet-18 with pretrained=True, which still works but is deprecated. The newer way is weights=ResNet18_Weights.DEFAULT.
  • Fix the visualization helper so it undoes the right normalization. It was still using the 0.5 mean and standard deviation from my CNN notebook instead of ImageNet's, so the sample images displayed with clipping warnings. It didn't affect training, but it's the kind of thing that could hide a real preprocessing bug.
  • Actually run the Vision Transformer on CIFAR-10. I want to know whether it would beat the fine-tuned ResNet-18 on the harder dataset, or whether a transformer trained from scratch on a dataset this small would just memorize it.
  • Try more regularization on the fine-tuned model to smooth out its training curves.
